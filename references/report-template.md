# 实验报告模板与证据标准

以下模板来自两类已验证的工作模式：分布式训练栈差异归因，以及多卡推理优化与正确性验证。按实验范围删减章节，但保留可复现性、对照关系、证据与结论边界。

## 报告骨架

```markdown
# <项目/模型>：<实验或性能主题>

> 文档状态：草稿 / 持续更新 / 已验证
> 当前版本：YYYY-MM-DD vX.Y
> 测试平台：<节点数> × <GPU 型号>

## 1. 目标与结论摘要
## 2. 环境、输入与测量口径
## 3. 当前性能/实验总表
## 4. 已确认的性能差异或复现结果
## 5. 性能差异归因与排查记录
## 6. 已实施优化与正确性门禁
## 7. 尚未完全控制的变量
## 8. 当前推荐配置
## 9. 当前结论边界与下一阶段计划
## 10. 更新记录
```

## 必填证据

### 复现

- 环境身份：硬件、驱动、运行时、镜像/依赖、代码 commit 或归档哈希。
- 用例身份：输入/数据来源和范围、seed、shape/序列长度、精度、并行策略、关键开关。
- 成功标准：loss/数值、输出质量、功能结果、长稳步数和资源边界。
- 原始材料：命令、完整配置、日志、产物或 trace 位置。

### 性能

- 明确 E2E 是否包含模型加载、JIT/首步、数据预处理、I/O 与保存；首步、稳态单步、diffusion/训练主体和总 E2E 分开报告。
- 用相同的测量窗口和统计方式比较方案；给出样本范围、均值或加权方法，以及 P50/P95（对长稳/抖动敏感时）。
- 在总表中标明“已验证 / 冒烟 / 运行中 / 失败 / 不纳入结论”。
- 仅比较相同模型、输入、精度、并行和计算量的指标；无法统一时分别列示，并写明不可比边界。

### 归因

- 给出 Profile 的设备关键路径/union 时间、主要类别占比、调用次数和通信—计算重叠。异步 API 或嵌套注解只作为线索，不直接等价为传输时长。
- 对通信，记录 group size、rank/节点映射、拓扑（机内/跨机/NVLink 等）、collective 类型、字节数/频次和暴露等待。
- 对算子，记录真实后端/kernels、shape、dtype、布局、调用/融合路径，以及候选替代实现的 real-shape microbenchmark。
- 将“观察到”“支持但未证实”“可以确认”分开写。不同类别重叠时，不把时间简单相加。

## 对照实验规则

| 目的 | 最小实验 | 合格条件 |
|---|---|---|
| 精度或策略收益 | 仅更改一个精度/策略开关 | 同一输入与指标下完成稳态比较 |
| 通信定位 | collective microbenchmark + 代表性 trace | 实际拓扑与暴露等待均有证据 |
| 算子替换 | 真实 shape 微基准 + 数值/语义 A/B | 先正确，再验证端到端收益 |
| 显存换通信 | 仅调整重建/reshard/prefetch 等策略 | 覆盖峰值显存与最长样本 |
| 长稳性能 | 固定配置完成预定步数 | 报告稳定窗口、尾延迟、异常次数 |

## 正确性门禁

性能数字只在对应路径通过以下合适层级后作为正式结论：

1. 单元或真实 activation 的数值/语义 A/B；
2. 最小端到端输入（如少步训练/采样）；
3. 完整目标 schedule 或代表性训练窗口；
4. 长稳、最长样本和资源边界验证。

若优化路径的输出质量、loss、收敛、内存或稳定性失败，其性能只可作为探索记录，不能称为最终最优。

## 结论措辞

- **可以确认**：有对照、profile/日志或正确性证据，且已完成预设验证窗口。
- **当前最佳**：在列出的约束、数据和版本下性能最高，并非普遍最优。
- **未观察到收益**：测试窗口内无显著端到端改进；不推断底层实现完全相同。
- **尚不能确认**：缺少同口径对照、必要 trace、真实输入验证或长稳验证。
- **不应表述为**：把训练栈、模型实现、精度、并行和统计口径同时变化的结果归因给单一框架或算子。
