# 报告连续性审计：让人决策，让接手者执行

正式实验报告应服务两类不同的读取方式：

- **决策摘要层**：让读者在短时间内理解当前结论、建议、证据强度和风险。
- **接手执行层**：让未参加实验的同事或智能体能够复现已知结果、判断当前运行状态，并在授权范围内继续、暂停或安全停止工作。

两层都应高信息密度。摘要层不被命令、日志和路径淹没；执行层不重复摘要叙述，而是提供可定位、可操作的事实。

## 决策摘要层

将下列内容放在报告前部，通常不超过理解决策所需的篇幅：

1. **目标与当前结论**：研究的问题、已达成的结果、尚未达成的目标。
2. **建议与优先级**：下一步应做什么、预期影响、关键风险与不应继续投入的方向。
3. **关键证据**：共同条件下的结果表、最有解释力的 profile/对照证据、正确性或画质门禁状态。
4. **边界**：结论在哪些模型、数据、版本和测量范围内有效；哪些问题尚不能确认。

使用短段落、表格和必要的图，而不是把时间线、命令或全部异常逐条展开。每一个重要数字应能在执行层找到原始证据位置。

## 接手执行层

按需从以下项目选择，不必为了完整而填充未知信息：

### 1. 当前状态

- 当前任务是已完成、运行中、失败、暂停还是探索性结果；最后确认时间。
- 对运行任务：运行标识、当前 step/epoch、最近 checkpoint、健康信号、预计或未知的完成条件。
- 对失败任务：最后一个成功阶段、错误摘要、已尝试与未尝试的恢复方法。

### 2. 最小复现路径

- 代码仓库与 commit、镜像/运行时/驱动版本、硬件与拓扑。
- 输入/数据边界、seed、关键 shape、精度、并行配置和配置文件位置。
- 启动或复现命令及其工作目录；对需要的数据、凭据或权限，仅写申请路径和前置条件，绝不写秘密本身。
- 成功标准：数值、画质、功能、性能、长稳或资源边界中哪些必须通过。

### 3. 证据与产物索引

用短表格列出每个结论的证据和位置：原始日志、profile/trace、配置、checkpoint、输出、关键帧或视频、文件 hash（可用时）。大文件存放在合规产物系统，报告提供名称、版本或路径引用，不复制内容。

### 4. 接下来怎么做

将剩余工作写成可执行项，每项包含：

- 要验证的假设或目标；
- 最小实验/操作；
- 预期观测与成功判据；
- 资源、风险和需要的授权；
- 停止、回退或升级条件。

把已经证明无收益、不可用或有正确性问题的路径单列，防止接手者重复探索。

## 交付前自问

完成报告后逐项自问，并将未能回答的项目写到“接手缺口”中：

| 自问 | 缺失时要明确提出的最小问题 |
|---|---|
| 陌生接手者能否在不问原作者的情况下复现当前基线？ | 需要哪份配置、commit/镜像身份、输入说明、数据权限或启动命令？ |
| 对仍在运行的任务，接手者能否知道它是否健康并查看进度？ | 最新任务标识、日志位置、监控命令、step/checkpoint、健康阈值和最后确认时间是什么？ |
| 接手者能否安全继续或停止？ | 下一条安全操作、写入目标、停止/回退条件，以及谁需要授权？ |
| 每项重要结论是否能追溯到可访问证据？ | 缺哪份日志、trace、A/B、质量门禁或统一口径的统计？ |
| 结论与下一步是否被清楚区分？ | 哪些是已验证事实，哪些只是推断或运行中工作？ |
| 还需要向用户提问什么？ | 数据/权限边界、验收目标、真实负载、输出质量要求、预算或生产修改授权中哪项未明确？ |

不要将所有问题抛回用户。先完成可从现有材料确定的部分，只对会改变实验范围、外部写操作或结论可信度的缺口提问。

## 飞书报告落地

在飞书原生文档中，使用一级标题区分“决策摘要”和“接手执行层”。摘要层保留总表与少量关键证据；执行层使用小节和表格列出状态、复现路径、证据索引与下一步。产物附件按照 [飞书报告与媒体交付](lark-report-delivery.md) 处理。写入后重新读取相关章节，确认链接、资源和表格没有丢失。
