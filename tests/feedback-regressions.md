# 真实反馈回归记录

本文件记录已经转化为可泛化验收场景的真实反馈。它不收集用户数据、实验产物、访问令牌或完整日志；仅保留足以解释规则变化的最小上下文。

## 记录格式

```markdown
## FR-XXX：<简短问题>

- 触发：<用户请求或可观察情境的脱敏摘要>
- 缺口：<旧工作流为什么无法满足>
- 修正：<新增或调整的 Skill 行为>
- 边界：<何时适用，何时不适用>
- 回归：<tests/acceptance-cases.md 的对应场景>
- 关联：<Issue / PR>
```

## FR-001：原生飞书报告与视频交付

- 触发：用户希望实验报告能直接维护飞书原生文档，并更友好地呈现视频生成实验的附件。
- 缺口：原 Skill 只规定报告内容和 Markdown 结构，未定义飞书文档读写、写后核验或媒体交付流程。
- 修正：飞书 Docx/Wiki 的语义读写优先使用 `lark-cli`；视频采用关键帧/缩略图预览、具名原始附件和复现实验元数据的两层交付。
- 边界：只在用户要求创建、读取或更新飞书报告时启用；不强制本地 Markdown、纯文本或其他文档系统切换到飞书。
- 回归：验收场景 D、F。
- 关联：Issue #1，PR #4。
